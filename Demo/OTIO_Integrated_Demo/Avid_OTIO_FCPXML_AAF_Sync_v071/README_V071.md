## Reproducibility

Run `python extract_aaf_picture_sync.py` to regenerate `sync_manifest.json` from `avid_aaf_structure.json` and `avid_multicam_v12_native_roundtrip.otio`. `python generate_v07.py avid_multicam_v12_native_roundtrip.otio --sync sync_manifest.json --out outputs/avid_picture_1406_frames_AAF_SYNC.fcpxml --report outputs/aaf_sync_report.json` generates the XML. `python -m unittest discover -p 'test*.py' -v` runs the tests. No aaf2 dependency is necessary for this bundled AAF structure dump; the dump was extracted previously from the original AAF. Direct fresh extraction will require pyaaf2 and the original AAF file.

## Caveats

An imported Resolve FCPXML may reorder source tracks or normalise audio topology. This is not a certified archival transfer. Existing OTIO media records do **not** natively encode every backed recording placement, so the exporter currently uses an **external AAF-derived sync manifest**. This is intentional: it demonstrates the missing schema data, rather than claiming the original OTIO alone was sufficient. The XML has not yet been imported into Resolve. Original file paths may need relinking. All converter code, documents, and tests were generated by ChatGPT; the user provided the original NLE fixtures, requirements and validation.
