# Experimental OTIO multicam SchemaDef — v1.4

> **Experimental, not an OTIO standard.** This is a proof of concept for representing editable multicams and recursive compositions in OpenTimelineIO. It requires the accompanying custom `SchemaDef` plugin. Existing OTIO-aware editors/viewers are not expected to reconstruct these structures without importer changes.
>
> **AI disclosure.** The schema design, code, synthetic fixtures, tests and documentation were generated by ChatGPT (OpenAI). The project contributor supplied the real-world NLE source projects, editing requirements and corrections, and ran the reported macOS Python/OTIO tests. The code and interpretations have not been independently reviewed.

| --- | --- | --- |
| [`avid_multicam_v12_native_roundtrip.otio`](avid_multicam_v12_native_roundtrip.otio) | Avid-derived multicam edit with separate picture/audio selections, shared source references, source media identity and original AAF provenance | Generated from a real Avid AAF extraction; round-tripped through OTIO on macOS |
| [`nested_recursive_typed_native_roundtrip.otio`](nested_recursive_typed_native_roundtrip.otio) | An outer multicam with a four-box angle containing four independently selected occurrences of another multicam; a fill/key graphics composition as another angle | Synthetic fixture designed to stress-test recursive composition semantics; round-tripped through OTIO on macOS |

These two files demonstrate **data representation and serialization**, not playable/rendered output or native editing behaviour in Avid, Premiere or Resolve. The original, pre-round-trip fixtures are `avid_multicam_v12.otio` and `nested_recursive_typed.otio` in the full package.

## Schema approach

The experimental plugin defines reusable composition definitions, occurrence-specific references, fixed-selection multicam selectors, numeric angle IDs scoped to a selectable group, output references, media identity/locator records, and typed composite outputs. Each video or audio edit segment has one selection; audio and video can have independent cut boundaries. Nested occurrences retain independent selection state even when they refer to the same shared definition.

The files use a custom `MulticamPackage` root rather than a standard OTIO `Timeline` root. This is **one exploratory architecture**, not a proposal to adopt these exact classes unchanged. AAF-specific source slots and MobIDs remain provenance, distinct from portable angle IDs.

## Inspect with OpenTimelineIO (Python)

Place `multicam_schemadef.py`, `manifest.json` and the OTIO fixtures in the same directory (they are included in the [v1.4 package](OTIO_Multicam_Schema_v1_4.zip), if hosted here). Install `opentimelineio` into your Python environment, then from that directory run:

```bash
export OTIO_PLUGIN_MANIFEST_PATH="$PWD/manifest.json"
python - <<'PY'
import opentimelineio as otio

for filename in (
    "avid_multicam_v12_native_roundtrip.otio",
    "nested_recursive_typed_native_roundtrip.otio",
):
    obj = otio.adapters.read_from_file(filename)
    print(filename, type(obj).__name__,
          "definitions:", len(obj.definitions),
          "selectors:", len(obj.selectors))
PY
```

Keep each deserialized package in a variable when accessing OTIO's C++-backed collections; chained access from a temporary object may raise an `AnyVector` lifetime error.

To reproduce the project tests from the **unpacked full v1.4 package**:

```bash
python -m unittest discover -p 'test*.py' -v
python conformance_report.py
export OTIO_PLUGIN_MANIFEST_PATH="$PWD/manifest.json"
python check_v13_runtime.py
```

## Validation and limits

- **Passed on macOS:** 24 v1.3 tests and native OTIO read/write/read for both fixtures. Subsequently, the v1.4 package passed 30 Python regression/conformance tests on macOS.
- **AAF writer:** A separate experimental writer generated an offline-placeholder AAF and reopened it using `pyaaf2`. This is **not** a full typed OTIO → source-linked, editable Avid multicam round-trip.
- **Not demonstrated:** third-party OTIO importer support; native multicam reconstruction in any NLE; graphics rendering; complete composite effect translation; independent code review.
- **Relinking:** AAF-derived media records preserve source identity, original locator/timecode evidence and audio channel provenance where recovered. Locator values do **not** verify that files exist at those paths.
- **Import fallback:** the draft discusses capability declarations and explicit loss reporting; support by real importers has not been verified.
